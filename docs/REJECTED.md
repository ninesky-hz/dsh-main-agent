# 否决清单：想清楚过、然后**没做**的那些事

这份清单只收一种东西：**真正被认真考虑过、然后被否掉的方案**。写它的用处不是记账，
是省掉下一次重复论证 —— 下一个人（或下一轮的我）想再提一遍时，先看「重开条件」那
一列，如果条件没被满足，那这次讨论到此为止。

「重开条件」必须是**可判定**的一句话：能对着代码或产物直接回答「满足 / 不满足」。
写「以后再说」「看情况」「等有需要」的行不算数（`tests/docs-coverage.test.mjs` 会红）。

## 清单

| 否决的内容 | 理由 | 什么条件下可以重开 |
| --- | --- | --- |
| 引入 SQLite 做状态存储 | 状态文件是人和 agent 都要**直接读、直接改、直接 git diff** 的东西；一旦进了二进制库，`.agi/progress.jsonl` 就不再是能 `tail -f` 的文本，排查一次停摆要先写 SQL。当前状态量是「每次循环追加一行」，JSONL 的写放大约是全部成本 | 出现跨进程并发写同一个状态文件、且已经实测到 JSONL 的读-改-写丢行时 |
| 引入 Source / Thread / Subscription / Correlation 全套模型 | 那是多用户、多来源的会话系统才需要的四层抽象；本插件只有一个 workspace、一个 Lead、一个 worker 池，四层里有两层永远只有一个实例。先把「谁在用哪份状态」这件事说清，比先建四张表便宜 | 同一个 workspace 里同时存在 ≥3 个来源（用户消息、定时提醒、外部 webhook）且它们的写入需要互相仲裁时 |
| 搬 Mandate 全量（只取 revision） | Mandate 的价值在于「目标是同一份、改动可追溯」，而这两件事在 GOAL.md 上只需要一个 `revision` 字段加 SHA 指纹就成立；全量搬会连带搬来它的审批流与角色模型，那套东西在这个插件里没有对手方 | 需要**跨会话**审批同一次目标变更（两个人先后批同一份 GOAL.md）时 |
| 做六标签页面板 | 面板的第一性收益只有两条：「分类可检验、互斥、覆盖全部」和「健康信息不占正文空间」。六个标签页是这两条原则的一种实现，不是唯一实现，先把两条原则落进 BRIEF 与 `/supervisor/health`，等它们真的不够用再说 | `/supervisor/health` 的响应字段 ≥ 20 个、或 BRIEF 正文因为塞健康信息超过 200 行时 |
| 重命名既有函数来贯彻命名纪律 | 193 处导出里 86 个函数不符合四类动词，重命名是一次横跨一万行、每个调用点都要跟的改造，风险与收益不成比例。棘轮（例外表只许减）能用十分之一的代价拿到同样的收敛方向 | 某次改动已经要碰某个文件里 ≥5 个不合规函数时（那时改名是顺手的，不是额外的） |
| 给 worker 暴露本插件的工具（goal / control / checks） | worker 的职责是「做完一件被交代的事」，它能看见 goal 就会自己改目标，能看见 control 就会自己给自己发指令。正面表（worker 零工具）不是保守，是防止把监督关系变成平级协商 | 出现必须由 worker 自己续行的任务类型，且已有一次实测证明「Lead 不在场就会卡死」时 |
| 在 worker 侧保留 `ask_user_question` | 用户是 Lead 的用户，不是 worker 的。worker 直接问用户会绕过 Lead 的分诊：问题没有上下文、回答没有落账、Lead 也不知道答案已经给过了。所有提问统一走 report 的 `question` 行 | worker 需要提的问题**无法**用一句话表达，且实测出现「经 Lead 转述后问题变形」的案例时 |
| 把 BRIEF / goal 这类易变内容塞进 system prompt | system prompt 是缓存前缀，往里面塞每轮都变的东西等于每轮把缓存打掉一次（这是可测的成本，不是猜测）；而且 system prompt 一旦包含状态，它就不再是「规则」而是「快照」，读的人分不清哪句还成立 | 提示词缓存不再按前缀命中（例如宿主改成按段落缓存）且实测缓存命中率不再随 BRIEF 变化时 |
| 自动 commit / push | 提交是人的动作。agent 自动提交会把「哪些改动是它做的」这条线索抹平，也会让 `git log` 失去「一次提交 = 一个决定」的粒度；本仓库的每次交付都由人看过 diff 再提交 | 仓库有独立的、只写不读的分支（例如 `agent/scratch`）且该分支永不合并时 |

## 怎么用这份清单

提一个新方案时，先在上表里找有没有同类的行。有，就对着「重开条件」那一列回答一句
「满足 / 不满足」；不满足就不要再花时间论证，满足就直接重开并在同一行注明为什么现在
条件成立了（改成新的一行也可以，旧行留着当历史）。
