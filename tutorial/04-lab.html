第 I 部分 —— 基础

你的实验场

带你走一遍你在安装页启动的那套干净部署 —— 进程、home 目录、磁盘上的会话、Web UI —— 再给你一张很短的安全规则清单，让你接下来整门课拿它做实验时，它还能好好的。

正在跑的进程

安装页启动了一个 dsh web 进程。在另一个终端里核实这个进程和它的 HTTP 端点： 

pgrep -af 'dsh web'
curl -I http://127.0.0.1:3080/

它在 http://127.0.0.1:3080 上提供 Web UI（这是默认值 —— $HOME/src/deepseek-harness/README.md，“Run”）。左侧边栏列出各个工作区及其会话；点一个 会话就能看到完整对话；底部的输入框直接和这个会话的 agent 对话。新建会话时要选一个 preset —— 第 6 章之后，你的 main-agent 就会出现在这个选择器里。

规则 1 —— 绝不对着同一个 home 起第二个 dsh

一个 $DSH_HOME，只能有一个进程。第二个 dsh 指向同一个 home，会把正在写的 会话日志搞坏。如果你确实需要重启这个进程（在这门课里很罕见 —— profile 补丁是热加载的），就回到 跑着它的那个终端，按 Ctrl-C，等它退干净，然后在同一个终端里重新启动： 

dsh web

harness 的 home：$HOME/.dsh

除非你刻意导出过 DSH_HOME，否则 Harness 默认就是 $HOME/.dsh。这门课用的 就是这个干净机器的默认值。所有会变的东西都住在这儿： 

$HOME/.dsh/
  profiles/web/
    package.json        ← which bundles this profile stacks (chapter 3)
    cordis.patch.yml    ← your live-watched override layer
  .agent-presets/       ← user-owned/package-installed presets land here (no main-agent yet)
  sessions/             ← every session, as directories of JSONL logs
  settings.yaml         ← legacy settings doc (imported once at boot, then renamed .imported)
  .credentials.yaml     ← managed credentials
  storages/             ← small JSON caches (session projections, workspaces)

这里有四样跟本课程直接相关：

  • profiles/web/package.json —— 第 6 章的 plugin 命令会安全地加上 supervisor 的依赖和 bundle 条目；不要手工编辑它。
  • profiles/web/cordis.patch.yml —— 通常不用动；它只用于明确的覆盖。
  • .agent-presets/ —— 第 6 章的安装器会在这里放一份 main-agent/ 兼容副本（目录不存在时才写）。注意 0.2.x 起宿主不再读取这个目录： 真正让 preset 出现在挑选器里的是 bundle patch 里的声明行，也就是 presets/main-agent.patch.yml（第 6 章第 3 步）。
  • sessions/ —— 对你来说只读，但信息量极大。下一节细说。

磁盘上的会话 —— 你免费的 trace 查看器

第 3 章说，会话在磁盘上是一份逻辑上的 JSONL 日志。默认它按帧压缩成 session.jsonl.zstd。会话按工作区目录分组： 

find "$HOME/.dsh/sessions" -name 'session.jsonl.zstd' | head

LOG=$(find "$HOME/.dsh/sessions" -name 'session.jsonl.zstd' | head -1)
zstd -dc "$LOG" | head -3

随便打开其中一个文件，你就会认出第 3 章那套词汇：turn/start、 user/message、tool/call、tool/result、assistant/message、 turn/end —— 一行一个 JSON 对象，只追加。对你的监督者来说有两个后果：

  • 查看 worker 靠 grep 就够了。Main Agent 想知道某个 worker 一直在干什么，用它本来 就有的那些 shell 工具去读这个 worker 的会话日志就行。不需要自定义 trace 插件 —— 这是对原方案里 subagent-trace 的原生优先替代。
  • Web UI 把同样的东西渲染出来给你看。每一个子会话都会像别的会话一样出现在边栏里， 带着完整对话和工具调用。你想要的那个“子代理标签页”已经有了，它叫会话列表。
动手试 —— 读一份真实的会话日志
  1. 在 Web UI 里随便打开一个已有会话，大致记一下里面发生了什么。
  2. 在上面那个工作区目录里，找到它对应的 session.jsonl.zstd 文件。
  3. zstd -dc <that-file> | grep -c 'tool/call' —— 数一下它有多少次工具调用；再用 zstd -dc <that-file> | grep -m1 'tool/call' | head -c 400 随便看一眼其中一次。

预期结果：这份 JSONL 和渲染出来的对话一个事件一个事件地对得上。等你觉得这事 理所当然的时候，你就已经搞懂了 harness 里头最重要的那个数据结构。

本课程用的工作区

agent 是在某个工作区里运行的（也就是会话的 cwd）。你的监督者是可搬的 —— 它的 状态全在 <workspace>/.agi/ 里 —— 所以给后面那些构建和测试的章节挑一个随手用的 工作区。安装页已经建好了；现在核实一下： 

test -f "$HOME/agi-lab/.agi/config.json"
find "$HOME/agi-lab/.agi" -maxdepth 2 -type f -print
cd "$HOME/agi-lab" && git init -q .   # optional: makes state changes diffable

在 Web UI 里，“新建会话”时可以把这个目录选作工作区。监督者和它的 worker 写下的所有东西，都落在它 下面。在干净基线上，你没有以前做过的监督者实验可以依赖。

安全规则

全部规则，集中放在这儿。它们来自随附的技能和部署自己的注释，不是出于“谨慎表演”：

规则为什么
绝不要改随附的 preset，也不要改 harness 检出目录。安装目录旁边的 agent-presets 目录和 $HOME/src/deepseek-harness 对你都是只读的。要改就先复制，改副本。 升级会覆盖安装目录；把 cordis preset 弄坏，等于把 Creator mode 本身弄没了。（editing-cordis-compositions，“Off-limits”。）
绝不在同一个 $DSH_HOME 上起第二个 dsh。 会把正在写的会话日志搞坏。
宿主平面的改动只写进 profiles/web/cordis.patch.yml，别处都不行。注意 YAML：重复的行 id 在组装时是致命的。 它是唯一被实时监听、又归用户所有的层；改错了，把文件还原回去就能撤销。
把 Creator mode 的会话当成 shell 权限来对待。 cordis preset 自己的文件头就是这么说的：它的工具会把模型写的 JavaScript 拿到活着的运行时里执行。（apps/cli/config/agent-presets/cordis/agent.cordis.yml，“TRUST”。）
大改之前先备份：cp $HOME/.dsh/profiles/web/cordis.patch.yml{,.bak} 补丁层坏掉时，最后一棵好用的树还在跑，但你总得有条方便的路回去。

面对 API key 的现实

模型调用需要你在安装页配置过的那条路由。Harness 把托管凭证和设置都存在 $HOME/.dsh 下； 你绝不要把 key 硬写进 preset、工作区或教程命令里。如果某条路由不通，先回 Settings → Models， 把标准会话里的一次提问跑通，再去调试你的监督者。

该养成的看板习惯

有三个习惯现在就该养成，因为后面每一个“动手试”都要用到它们：

  1. 盯着进程：让跑着 dsh web 的那个终端一直看得见。挂载错误、补丁重载失败、 插件崩溃都打在那里。
  2. 盯着树：dsh --profile web --dump-config | grep -n <row-id>，确认你加的 行真的被组装进去了。（在普通 shell 里跑就行；它不会起第二个服务器。）
  3. 盯着磁盘：find "$HOME/.dsh/sessions" -maxdepth 2 -type f | tail， 看着会话存储在干活的过程中冒出来。
动手试 —— 实验场检查清单

自动评分："$HOME/src/dsh-supervisor/tutorial/grade.sh" m0 --ws "$HOME/agi-lab" （见 $HOME/src/dsh-supervisor/tutorial/GRADING.md；本课程里每个里程碑框都配了一个对应的评分器）。

继续往下之前，确认这五条：

  1. 只有一个 dsh web 进程在跑，并且 http://127.0.0.1:3080 能打开。
  2. $HOME/.dsh/profiles/web/package.json 和 cordis.patch.yml 都在。
  3. test ! -e "$HOME/.dsh/.agent-presets/main-agent" 返回成功。
  4. $HOME/agi-lab 存在。
  5. 你打开过一份会话 JSONL，并且认出了那些事件类型。
